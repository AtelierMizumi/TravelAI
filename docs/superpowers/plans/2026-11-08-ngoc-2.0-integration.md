# Ngoc TravelAI 2.0 Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Ngoc's TravelAI 2.0 first as an unmodified baseline, then as an integrated build in this repo, and test it on desktop web and a physical Android phone, ending with a defect list.

**Architecture:** Phase A runs upstream untouched in a directory outside this repo. Phase B imports its snapshot into a git worktree on branch `integration/ngoc-2.0` at upstream paths (`apps/mobile`, `backend/`), keeps `services/ai` as the AI service, and adds profile-gated v2 services to docker-compose. Expo runs on the host (needed for the phone).

**Tech Stack:** Expo SDK 58 / RN 0.88, Spring Boot 3.5.14 (Java 25 in Docker, Java 21 on host with `-Djava.version=21`), PostgreSQL 16, FastAPI + Google Cloud Vision, Docker Compose, adb.

**Spec:** `docs/superpowers/specs/2026-11-08-ngoc-2.0-integration-design.md`

## Global Constraints

- Upstream: `https://github.com/ngoctapcodee/travel-ai-system`, head `5799682`. No shared history, so snapshot import only, no `git merge`.
- Do not rename upstream packages; keep upstream paths. `client/` and `services/core` stay untouched.
- `services/ai` is the authoritative AI service; upstream `ai-service/` is reference only and is not imported.
- Desktop = Expo Web in a desktop browser. Mobile = physical Android only. iOS out of scope.
- Fresh PostgreSQL 16 in Docker; no existing database touched; never `rm -rf` outside the paths this plan creates.
- Service-account key stays at `$HOME/service-account.json` (outside every repo). It is never copied into a repo tree, baked into an image, committed, echoed, or logged. Containers get it by read-only volume mount only.
- No commit or push unless the owner asks. Never touch `main`. When committing: owner's git identity, Conventional Commits with issue ID, no assistant trailers, run `scripts/governance-check.sh` first, no `*.pdf/docx/xlsx/csv` in the diff.
- Cross-scope (Ngoc/Duc areas) is allowed here only at the owner's explicit request; flag it in the PR.

## Review Focus

Failure modes the spec implies but happy-path tests miss, most likely first. Each is pinned by a step in the task named in brackets.

1. Fresh DB has no tour schedule, inventory or simulated bank account, so booking/payment must fail with a clear 4xx message, not a 500 (upstream warns about this). [Task 3, Task 5]
2. Phone calls `localhost`/LAN host that it cannot reach: the app must show an error state, not hang or crash. [Task 6]
3. `POST /detect` with no consent, a non-image, an oversized file, or HEIC must give 4xx (HEIC normalized by the app), never 500. [Task 4]
4. Missing or invalid Google credentials: `GET /` reports `googleVisionConfigured=false` and `/detect` returns 502/503 with a message; process does not crash. [Task 4]
5. Backend started without the message-key file must fail fast with a readable error; browser origin `http://localhost:8084` must pass CORS. [Task 3]
