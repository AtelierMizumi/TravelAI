# TravelAI production runbook (PC as VPS)

Public URL: `https://travelai.minhthuan.dev` (Cloudflare Tunnel `travelai-pc` -> Caddy -> v2 services).
Compose project: `travelai-prod` (separate from the dev stack). Nothing publishes a host port.

## Start / stop
- Start (builds web bundle, generates missing secrets, starts everything): `scripts/up.sh`
- Stop (keeps data): `scripts/down.sh`   Never add `-v`: it deletes the database volume.
- Status: `docker compose -p travelai-prod ps`

## Verify
- `scripts/smoke-edge.sh https://travelai.minhthuan.dev` must print only PASS.
- Tunnel connected: `docker logs travelai-prod-cloudflared-1 2>&1 | grep -c "Registered tunnel connection"` -> 4.

## Configuration (`.env`, mode 600, gitignored)
`POSTGRES_PASSWORD`, `HOST_MESSAGE_KEY` (generated by `scripts/gen-secrets.sh`), `HOST_GCP_KEY` (path to the service-account JSON),
`CLOUDFLARE_TUNNEL_TOKEN`, `PUBLIC_ORIGIN`. Never paste these into chat, commits, build args or `EXPO_PUBLIC_*`.

## Changing the domain
1. Cloudflare -> Tunnels -> `travelai-pc` -> Routes: add the new hostname -> `http://caddy:80`.
2. Set `PUBLIC_ORIGIN` in `.env`, run `scripts/up.sh` (CORS/WebSocket origin and the web bundle are rebuilt).
3. Rebuild the Android APK: its URL is baked in.

## Rotate a secret
- `POSTGRES_PASSWORD`: change it in `.env` AND inside Postgres (`ALTER USER`); otherwise the backend cannot connect.
- Message key: rotating it makes existing chat messages unreadable; only do it on an empty chat table.
- Tunnel token: Cloudflare -> Tunnel -> Refresh token, update `.env`, `scripts/up.sh`.

## Survive a reboot
`docker` is enabled in systemd and every service is `restart: unless-stopped`; after a reboot the stack and tunnel return on their own.
Keep the PC awake (disable suspend) and plugged in during grading. Verify after a real reboot with the smoke script.

## Backup / restore
`docker exec travelai-prod-postgres-v2-1 pg_dump -U travelai_user travel_ai > ~/backups/travelai-$(date +%F).sql`
Restore: `docker exec -i travelai-prod-postgres-v2-1 psql -U travelai_user travel_ai < file.sql`.
Known limitation: schema is managed by `ddl-auto=update` (no migration tool).

## Tunnel down?
`docker logs travelai-prod-cloudflared-1 | tail`. Typical causes: no internet, wrong/refreshed token, route missing in the dashboard.

## Abuse controls
`/ai/detect` is unauthenticated by design. The edge rejects uploads over 10 MB. No hard Vision quota is set (owner decision, to avoid
self-throttling in a demo); consider a budget ALERT in Google Cloud so a spike is noticed.
