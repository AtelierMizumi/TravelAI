# TravelAI production runbook (PC as VPS)

Public URL: `https://travelai.minhthuan.dev` (Cloudflare Tunnel `travelai-pc` -> Caddy -> v2 services).
Compose project: `travelai-prod` (separate from the dev stack). Nothing publishes a host port.

## Start / stop
- Start (builds web bundle, generates missing secrets, starts everything): `scripts/up.sh`
- Stop (keeps data): `scripts/down.sh`   Never add `-v`: it deletes the database volume.
- Status: `docker compose -p travelai-prod ps`

## Verify
- `scripts/smoke-edge.sh https://travelai.minhthuan.dev` must print only PASS.
- Tunnel connected: `docker logs travelai-prod-cloudflared-1 2>&1 | grep -c "Registered tunnel connection"` -> 4.

## Automatic deploy (CD, pull-based)
- Flow: push to `DEPLOY_REF` -> CI (all jobs) -> job `publish` pushes `travelai-backend`, `travelai-ai`, `travelai-web` to GHCR tagged `sha-<12 hex>` ->
  `scripts/deploy-agent.sh` on this PC (systemd user timer, every 3 min) sees the newest green commit, pulls the images, backs up the database,
  starts the release and smoke-tests it. Smoke fails -> the previous tag is restarted and the bad commit is remembered (no retry loop).
- Nothing connects into this PC and the agent holds no credentials: the repo and the images are public and contain no secrets
  (secrets are mounted at runtime from `~/deploy/travelai/.env` and `secrets/`).
- One-time install on the PC (needs your own shell, see `deploy/systemd/`):
  ```bash
  mkdir -p ~/.config/systemd/user
  cp ~/deploy/travelai/deploy/systemd/travelai-deploy.{service,timer} ~/.config/systemd/user/
  systemctl --user daemon-reload && systemctl --user enable --now travelai-deploy.timer
  loginctl enable-linger "$USER"   # keep the timer running without an open session
  ```
- Once the agent manages production, do not run `scripts/up.sh` from a development checkout: it rebuilds local images and replaces the released ones.
  Production is operated from `~/deploy/travelai` only (`up.sh` there is for first-time bootstrap).
- Files: `~/deploy/agent.env` (`DEPLOY_REF`, `REPO`), `~/deploy/state/{current.sha,current.tag,bad.sha}`, `~/deploy/history.log`, `~/deploy/backups/before-<tag>.sql` (last 10).
- Watch: `tail -f ~/deploy/history.log`, `systemctl --user list-timers travelai-deploy.timer`, `journalctl --user -u travelai-deploy.service -e`.
- Pause deploys: `systemctl --user stop travelai-deploy.timer`. Re-try a commit marked bad: `rm ~/deploy/state/bad.sha`.
- Switch the tracked branch (e.g. after the v2 merge into `main`): edit `DEPLOY_REF` in `~/deploy/agent.env`.
  The branch must also be listed under `on.push.branches` in `.github/workflows/ci.yml`; otherwise no green push run exists and the agent silently keeps the current release. Current tracked branch: `feat/wbs-1.8.2-v2-integration`.
- Manual rollback: run `TRAVELAI_TAG=sha-<12 hex> docker compose -p travelai-prod --profile v2 -f docker-compose.yml -f docker-compose.edge.yml -f docker-compose.release.yml up -d --no-build` inside `~/deploy/travelai`.
- Limits: a deploy takes up to a few minutes after CI finishes; the PC must be on; failure notification is the log and a desktop notification (no commit status, that would need a token).

## Configuration (`.env`, mode 600, gitignored)
`POSTGRES_PASSWORD`, `HOST_MESSAGE_KEY` (generated by `scripts/gen-secrets.sh`), `HOST_GCP_KEY` (path to the service-account JSON),
`CLOUDFLARE_TUNNEL_TOKEN`, `PUBLIC_ORIGIN`. Never paste these into chat, commits, build args or `EXPO_PUBLIC_*`.

## Changing the domain
1. Cloudflare -> Tunnels -> `travelai-pc` -> Routes: add the new hostname -> `http://caddy:80`.
2. Set `PUBLIC_ORIGIN` in `.env`, run `scripts/up.sh` (CORS/WebSocket origin and the web bundle are rebuilt).
3. Rebuild the Android APK: its URL is baked in.

## Rotate a secret
- `POSTGRES_PASSWORD`: change it in `.env` AND inside Postgres (`ALTER USER`); otherwise the backend cannot connect.
- Message key: rotating it makes existing chat messages unreadable; only do it on an empty chat table.
- Tunnel token: Cloudflare -> Tunnel -> Refresh token, update `.env`, `scripts/up.sh`.

## Survive a reboot
`docker` is enabled in systemd and every service is `restart: unless-stopped`; after a reboot the stack and tunnel return on their own.
Keep the PC awake (disable suspend) and plugged in during grading. Verify after a real reboot with the smoke script.

## Backup / restore
`docker exec travelai-prod-postgres-v2-1 pg_dump -U travelai_user travel_ai > ~/backups/travelai-$(date +%F).sql`
Restore: `docker exec -i travelai-prod-postgres-v2-1 psql -U travelai_user travel_ai < file.sql`.
Known limitation: schema is managed by `ddl-auto=update` (no migration tool).

## Tunnel down?
`docker logs travelai-prod-cloudflared-1 | tail`. Typical causes: no internet, wrong/refreshed token, route missing in the dashboard.

## Abuse controls
`/ai/detect` is unauthenticated by design. The edge rejects uploads over 10 MB. No hard Vision quota is set (owner decision, to avoid
self-throttling in a demo); consider a budget ALERT in Google Cloud so a spike is noticed.
